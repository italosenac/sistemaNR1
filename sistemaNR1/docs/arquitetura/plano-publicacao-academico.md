1. **Supabase:** o histórico remoto do projeto `sfutycdmcjsvmfrvtxam` contém E1, `20260928000100`–`20260928001000` e `20260928001100`. A auditoria confirmou nove tabelas com RLS/FORCE RLS, funções e login restrito; a `01100` corrigiu o EXECUTE excedente da função interna de gatilho. Não usar `db reset` nem reescrever migrações aplicadas. O Auth usa `https://sistemanr1-web-academico.vercel.app` como Site URL e os redirects exatos `/auth/confirmacao` e `/atualizar-senha`; as URLs anteriores foram preservadas. A [documentação oficial](https://supabase.com/docs/guides/auth/redirect-urls) descreve essas URLs. Os testes usaram links administrativos para fixtures existentes, sem envio de e-mail.
2. **Render / NestJS:** o Git conectado contém o workspace em `sistemaNR1/` dentro da raiz do repositório. Configurar **Root Directory `sistemaNR1`**, mantendo `apps/api` e `packages/contratos` acessíveis; não usar `apps/api` como raiz. Usar Node 24 compatível com `engines.node`, confirmar pnpm 12.6.0 e construir com `pnpm install --frozen-lockfile && pnpm --filter @sistemanr1/contratos build && pnpm --filter @sistemanr1/api build`. Start: `pnpm --filter @sistemanr1/api start:prod` (entrada `apps/api/dist/main.js`); Health Check Path: `/health`. Configurar `NODE_ENV=production`, `PORT` do serviço, `FRONTEND_URL=https://<dominio-vercel>`, `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`, `DATABASE_URL` do login **restrito** e `DATABASE_CA_CERT_PATH=/etc/secrets/supabase-ca.crt`. Carregar a CA oficial como Secret File privado, sem commitar ou registrar seu conteúdo. O driver mantém `rejectUnauthorized: true` e valida hostname. A [documentação do Render](https://render.com/docs/configure-environment-variables) descreve o caminho do Secret File; o [suporte a monorepos](https://render.com/docs/monorepo-support) descreve o diretório raiz. Chave secreta e URL PostgreSQL ficam somente no backend. Não configurar migração automática em build ou pre-deploy.
3. **Vercel / Next.js:** conectar a mesma branch com **Root Directory `sistemaNR1/apps/web`**, habilitando a inclusão dos arquivos de `sistemaNR1/packages/contratos` e do workspace fora dessa raiz. Usar Node 24 e verificar pnpm 12.6.0; se a detecção do gerenciador divergir, habilitar `ENABLE_EXPERIMENTAL_COREPACK=1` antes da instalação. Instalar com `pnpm install --frozen-lockfile` e construir contratos + web com `pnpm --filter @sistemanr1/contratos build && pnpm --filter @sistemanr1/web build`. Conferir a detecção do artefato Next em `apps/web/.next`. Configurar somente `NEXT_PUBLIC_API_URL=https://<api-render>`, `NEXT_PUBLIC_SUPABASE_URL` e `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`; essas variáveis entram no bundle do navegador durante o build. A chave secreta, a CA e `DATABASE_URL` jamais pertencem ao projeto Vercel. A [documentação de monorepos](https://vercel.com/docs/monorepos/monorepo-faq) descreve a inclusão de arquivos externos; a [documentação de build](https://vercel.com/docs/builds/configure-a-build) descreve Corepack.
