2. **Render / NestJS:** o Git conectado contém o workspace em `sistemaNR1/` dentro da raiz do repositório. Configurar **Root Directory `sistemaNR1`**, mantendo `apps/api` e `packages/contratos` acessíveis; não usar `apps/api` como raiz. Usar Node 24 compatível com `engines.node`, confirmar pnpm 12.6.0 e construir com `pnpm install --frozen-lockfile && pnpm --filter @sistemanr1/contratos build && pnpm --filter @sistemanr1/api build`. Start: `pnpm --filter @sistemanr1/api start:prod` (entrada `apps/api/dist/main.js`); Health Check Path: `/health`. Configurar `NODE_ENV=production`, `PORT` do serviço, `FRONTEND_URL=https://<dominio-vercel>`, `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`, `DATABASE_URL` do login **restrito** e `DATABASE_CA_CERT_PATH=/etc/secrets/supabase-ca.crt`. Carregar a CA oficial como Secret File privado, sem commitar ou registrar seu conteúdo. O driver mantém `rejectUnauthorized: true` e valida hostname. A [documentação do Render](https://render.com/docs/configure-environment-variables) descreve o caminho do Secret File; o [suporte a monorepos](https://render.com/docs/monorepo-support) descreve o diretório raiz. Chave secreta e URL PostgreSQL ficam somente no backend. Não configurar migração automática em build ou pre-deploy.
