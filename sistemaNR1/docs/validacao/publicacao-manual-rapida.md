# Publicação manual rápida — caso as integrações não estejam conectadas

Usar a branch `italo_SDD` do repositório `italosenac/sistemaNR1`. O workspace está em `sistemaNR1/` dentro da raiz Git. Não colar segredos no chat nem em arquivos versionados.

1. **Render:** criar serviço web Node pela branch `italo_SDD` ou importar o Blueprint `sistemaNR1/render.yaml`. Root Directory `sistemaNR1`; build `pnpm install --frozen-lockfile && pnpm --filter @sistemanr1/contratos build && pnpm --filter @sistemanr1/api build`; start `pnpm --filter @sistemanr1/api start:prod`; health `/health`. Confirmar Node 24 e pnpm 12.6.0 no log de instalação.
2. **Segredos Render:** inserir `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY` e `DATABASE_URL` do login **sistemanr1_runtime_e1** no painel privado. Adicionar a CA como Secret File `supabase-ca.crt`, com `DATABASE_CA_CERT_PATH=/etc/secrets/supabase-ca.crt`; manter `NODE_ENV=production`. Definir `FRONTEND_URL` quando a URL Vercel existir. O código exige TLS com `rejectUnauthorized: true`; não usar login admin.
3. **Vercel:** importar a mesma branch com Root Directory `sistemaNR1/apps/web` e habilitar a inclusão de arquivos fora da raiz para alcançar `packages/contratos` e `pnpm-lock.yaml`. Install `pnpm install --frozen-lockfile`; build `pnpm --filter @sistemanr1/contratos build && pnpm --filter @sistemanr1/web build`. Confirmar Node 24/pnpm 12.6.0; se necessário, habilitar `ENABLE_EXPERIMENTAL_COREPACK=1`. Configurar somente `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_SUPABASE_URL` e `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.
4. **Domínios:** usar a URL HTTPS efetivamente publicada pela Vercel em `FRONTEND_URL` no Render. No Supabase Auth, configurar Site URL e Redirect URLs exatas `/auth/confirmacao` e `/atualizar-senha` nesse domínio. Fazer novo deploy do frontend se `NEXT_PUBLIC_API_URL` tiver sido alterada após o build.
5. **Conferência:** abrir `https://<api-render>/health` e o frontend em navegador; testar login somente com uma das cinco fixtures comprovadas, CORS, navegação M1→M2→M3→PDF e download. Registrar URLs, horário, revisão e resultados no relatório. Não testar os dois perfis desconhecidos.

O Blueprint não contém segredos nem cria o Secret File. A [documentação do Render](https://render.com/docs/blueprint-spec) descreve Blueprints e a [configuração de Secret Files](https://render.com/docs/configure-environment-variables); a [FAQ de monorepos da Vercel](https://vercel.com/docs/monorepos/monorepo-faq) descreve os arquivos fora do Root Directory.
